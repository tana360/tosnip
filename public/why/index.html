Why ToSnip

The screenshot is on the clipboard. The CLI still cannot see it.

ToSnip is for that gap. Print Screen, then Ctrl+V, and an AI in a terminal can open the screen you captured. You do not save the file, and you do not type its name.

  • The clipboard
  • Chat labels
  • No install
  • Five minutes
  • Administrator
The problem

A terminal cannot open the clipboard

Press Print Screen for the whole screen, or Win + Shift + S and drag over one area. The picture stays on the clipboard. PowerShell, CMD, Windows Terminal, and an AI CLI accept text at the cursor. Ctrl + V in those windows does not place the picture. Saving the file yourself means you choose a folder, invent a name, and type that path.

How ToSnip fixes it

Install once on this PC. After that, Ctrl + V in Windows Terminal, PowerShell, PowerShell 7, or CMD writes a JPEG in C:\ToSnip and types the path at the cursor. The name is six characters, and you do not choose it. The width stays at most 1000 pixels. A smaller picture is not enlarged. The helper does not press Enter, so you still send the command yourself. Nothing from this path is uploaded.

The same picture, while the file is still there and the 5 minutes are not up, types the same path again. If the window in front changes while the file is saved, the path is copied and the bar tells you to press Ctrl+V. A path that contains a space is quoted. If a folder cannot be created at the drive root, the file is stored in LocalAppData\ToSnip\images. Pasting ordinary text still pastes that text.

The problem

[Image #1] is not a file

A chat inserts [Image #1] when a picture is attached. The number is only the order of pictures in that message, and the next message starts again at 1. ToSnip does not create the label. The label does not record that the picture was a screenshot, and a CLI cannot open it.

How ToSnip fixes it

ToSnip gives a path such as C:\ToSnip\a1b2c3.jpg, or a link such as https://tosnip.com/v/a1b2c3. The CLI opens that address and receives the picture.

The problem

Some windows should get a link, not a program

The AI may be in Cursor, VS Code, a Linux terminal, or Terminal on a Mac. Those windows do not receive a typed path from the Windows helper. Another person, or another machine, also needs a link rather than a folder on this disk.

How ToSnip fixes it

Open the web page and paste. Nothing is installed. The short link is copied. On a Mac the paste key is Command + V. Anyone who has the link can view the picture for 5 minutes. There is no account and no ads. The link is the key to the picture.

The problem

A screenshot should not stay

The screen you captured is often useful for a minute and then finished. A file left in a folder, or a link that still opens next week, keeps that screen around.

How ToSnip fixes it

The JPEG on this PC and the picture on the web last 5 minutes, then they are deleted. The old path and the old link no longer open. Pasting that exact picture again, with no different picture in between, is refused. Paste A, then a different picture, then A again, and the second A is kept.

The problem

An administrator window ignores a normal helper

A terminal opened with Run as administrator does not accept keystrokes from a program started the normal way. Ctrl+V can then fail to type the path.

How ToSnip fixes it

Start the helper as administrator when that terminal is an administrator. Otherwise paste on the web page and give the CLI the link.

Pick the path that matches the window

Use the web page when you want a link and nothing installed. Install on this PC when you want Ctrl+V to type a path in Windows Terminal, PowerShell, or CMD.
